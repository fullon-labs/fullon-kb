# 来源与核验规则

## 来源层级

1. 目标网络当前状态：chain ID、ABI、代码哈希、账户权限、gas 与排班。
2. 固定提交的官方源码：用于解释具体实现与命令参数。
3. 官方产品文档与 FAQ：保留来源和定位；产品目标与历史参数应与当前状态分开。
4. 内部笔记与草稿：只作为待核验线索。

本次源码基线：Core `2188e4f94a1e9fe564a31c33e497b464556f3650`；系统合约 `d34fc8f588e4bcc581e1377e729a248e0098f090`；RWID `d0fcb698711a0ea807515e76cf44e357d38787f3`；CDT `5c4b07b077b8bc9378c7e7adcf52b474fbf63c74`。本地源文件审阅不等于对远端分支、发布包或链上代码进行了验证。

## 更新约定

说明目标读者、目标任务、前提、步骤、完成标准、排错和来源。涉及当前网络参数须记录网络、来源与日期。新增命令要对照源码或实际 CLI；示例不得包含真实私钥、认证令牌或个人认证信息。

RPC 文档现已按 v0.9.2 重新核对，2026-11-02 为本次源码核验日期；独立的旧线上观察继续保留原日期，不能当作本次部署证据。[审阅清单](v0.9.2-audit.json)记录固定提交、源文件哈希和接口目录。发现资料冲突时注明差异，不通过修改日期或隐藏来源消除冲突。

## 发布边界

站点只构建 `docs/`，不构建仓库根目录 Agent 配置或 `docs_CisuMusiC_App/` 内部材料。未填充的历史模板不放在主导航。所有公开页面都应适合直接对外阅读。
