# 互操作性：代理账户与跨链流程

本文整理白皮书 v2.5.0 澄清稿（2026-11-02）的协议设计，不代表本次已验证各网络部署。

## 白皮书的设计路径

白皮书希望外部链用户保留原钱包签名习惯，通过 FullOn 代理账户参与部署在 FullOn 的 DApp，而不是要求每个应用都为不同链重复部署。

1. 用户持有外部链地址和密钥，在支持该流程的应用中发起绑定。
2. 绑定将外部公钥、地址与分配的 FullOn 代理账户关联。
3. 用户通过支持的桥接流程把资产转入 FullOn 侧。
4. 用户签署交互消息；代理矿工另行签署并提交 FullOn 交易。按白皮书，协议验证两类签名，并处理不同链的哈希、签名算法和序列化差异。
5. 用户可发起资产返回来源链的流程，代理账户仍可保持有效。

这里的“代理矿工”是代理提交交易的服务角色，不能直接等同于[Active/Standby BP](governance.md)的共识和奖励资格。

## 账户层与资产层分别核验

| 层次 | 需要确认 |
| --- | --- |
| 身份绑定 | 实际合约、签名域、支持的钱包/链、绑定和解绑规则 |
| 代理提交 | 服务可用性、消息 nonce/过期策略、费用和重试去重 |
| 资产跨链 | 支持的资产合约、验证/托管模型、确认数、暂停/退款与目标链入账规则 |
| DApp | 网络、动作授权、资产、业务结果及不可逆确认 |

白皮书描述两类签名验证，不等于给出了某一桥的完整证明协议或审计报告；同样不表示任意外部钱包、任意链和任意代币都已可用。文中提到充当 L2/侧链的架构方向，也不能当作已验证部署名单。

## 与其他账户类型的区别

- 原生/主权账户：FullOn 命名账户及其权限。
- EVM 地址账户：白皮书中只在 EVM 执行环境内有意义的地址，与原生账户之间需要资产桥接。
- 代理账户：绑定外部链身份，通过代理交互进入 FullOn。
- RWID：围绕真实世界身份因素与账户恢复的方案，不等于上述跨链代理机制。
