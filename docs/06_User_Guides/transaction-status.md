# 交易查询与到账确认

目标：区分钱包提示、链上执行和接收方入账。

1. 从钱包复制完整交易 ID，在相同网络的浏览器查询。
2. 核对交易执行状态，以及合约、动作、发送方、接收方、数量和 memo。仅有交易 ID 不能证明转账已执行成功。
3. 检查所在区块与不可逆状态；若浏览器只显示已打包，继续等待确认。开发者可比较区块号与 LIB，见[交易开发指南](../10_Developer_Guides/transactions.md)。
4. 若链上已成功但钱包余额未更新，刷新钱包并核对网络和代币；交易所未入账时，核对其确认数、最低金额及 memo 规则。

| 现象 | 含义与下一步 |
| --- | --- |
| 钱包已提交 | 已发起请求，还需查询执行结果 |
| 已打包但未不可逆 | 仍可能受分叉影响，继续确认 |
| 执行失败 | 阅读错误原因；不能作为成功付款凭据 |
| 查询不到 | 可能网络错误、尚未打包或索引未覆盖；不能直接判定失败 |
| 已成功且不可逆 | 链上执行已确认，接收服务仍可能有独立入账流程 |

查询不到时不要直接重发。保存交易 ID、提交时间和错误信息，再按[排错指南](troubleshooting.md)检查。
